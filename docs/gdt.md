# Глобальная таблица дескрипторов (`gdt.md`)

Глобальная таблица дескрипторов (GDT) — это обязательная структура данных процессоров x86, которая определяет базовые правила доступа к памяти (сегменты, права доступа, базовые адреса и лимиты) при переходе в 32-битный защищенный режим.

Фреймворк берет на себя всю рутину по побитовому сдвигу флагов и формированию сложной 8-байтовой структуры дескрипторов, генерируя чистый и понятный ассемблерный код для компилятора NASM.

---

## 🛠 Описание методов

### 1. Формирование таблицы (`setup_gdt`)

Метод автоматически собирает три обязательных дескриптора: **Null-дескриптор** (всегда забит нулями), **Дескриптор сегмента кода (Code)** и **Дескриптор сегмента данных (Data)**.

> 💡 **Справка для новичков:** Архитектура GDT перегружена низкоуровневыми флагами. Если вы только начинаете и не хотите разбираться в битовых масках, **просто вызывайте `setup_gdt()` без аргументов**. По умолчанию метод настроит память в режиме Flat Model (плоская модель), где сегменты кода и данных перекрывают все доступные 4 ГБ памяти. Этого более чем достаточно для старта любой ОС.

#### Основные параметры конфигурации (для продвинутых)

* **`base_code` / `base_data**` — Базовый физический адрес, с которого начинается сегмент (по умолчанию `0x00000000`).
* **`limit_code` / `limit_data**` — Максимальный размер сегмента (по умолчанию `0xFFFF`). При включенной гранулярности этот лимит умножается на 4 КБ, покрывая все 4 ГБ памяти.
* **`writable_data`** — Разрешает или запрещает запись в сегмент данных (`True` по умолчанию).
* **`read_code_data`** — Разрешает или запрещает чтение из сегмента кода (`True` по умолчанию).
* **`granularity_data`** — Флаг гранулярности. Если `True`, размер сегмента измеряется в страницах по 4 КБ, если `False` — в байтах.

### 2. Загрузка таблицы в процессор (`load_gdt`)

Метод генерирует ассемблерную команду `lgdt [gdt32_ptr]`. Она загружает адрес и размер созданной структуры в специальный системный регистр процессора — `GDTR`.

---

## 🗺 Анатомия сгенерированной структуры в памяти

После вызова `setup_gdt` фреймворк инжектирует в ассемблерный файл блок данных, который выглядит следующим образом:

* **`gdt_null`** — Слот `0x00`. Защитный пустой дескриптор.
* **`gdt_code`** — Слот `0x08`. Сегмент для исполнения кода (вызывается через дальний прыжок).
* **`gdt_data`** — Слот `0x10`. Сегмент для работы со стеком и данными.
* **`gdt32_ptr`** — 6-байтовый указатель (размер GDT минус 1 и её линейный базовый адрес), который считывается инструкцией `lgdt`.

---

## 💻 Пример использования

```python
# Передаем процессору адрес, где будет лежать таблица
boot.load_gdt()

# Генерируем сами данные GDT 
boot.setup_gdt()

```
