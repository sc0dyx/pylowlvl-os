# Переход в защищенный режим (`enable_protected_mode`)

Метод для переключения процессора из 16-битного реального режима в 32-битный защищенный режим (Protected Mode). Активация происходит путем установки нулевого бита (PE — Protection Enable) в системном регистре управления `cr0`.

---

## 🛠 Стратегии переключения: что выбрать?

Фреймворк поддерживает четыре разных метода установки бита PE в регистре `cr0`. Флаг `preserve_eax=True` позволяет сохранить исходное значение регистра `eax` через стек (`push`/`pop`), если его затирание критично для твоего кода.

### 1. Логическое ИЛИ (`method="or"`)

Классический и самый надежный способ. Считывает `cr0` в `eax`, делает `or eax, 1` (выставляет 0-й бит в единицу, не трогая остальные) и заливает обратно в `cr0`.

* **Плюсы:** Безопасно изменяет только бит PE. Стандарт для всех ОС.
* **Минусы:** Нет.
* **Вердикт:** **Основной выбор.** Самый предсказуемый и правильный вариант.

### 2. Инкремент (`method="inc"`)

Считывает `cr0` в `eax`, делает `inc eax` и отправляет обратно в `cr0`. Поскольку после сброса процессора остальные биты в `cr0` обычно равны нулю, прибавление единицы как раз выставляет 0-й бит (PE).

* **Плюсы:** Выглядит хакерски.
* **Минусы:** Опасно. Если в `cr0` уже были взведены какие-то другие младшие биты (например, MP или EM), `inc` устроит перенос разрядов и превратит конфигурацию регистра в кашу.
* **Вердикт:** **Ради фана.** Можно использовать только при полной уверенности, что `cr0` чист.

### 3. Загрузка слова состояния машины (`method="lmsw"`)

Использует древнюю инструкцию `lmsw` (Load Machine Status Word) родом из процессора Intel 286. Напрямую загружает значение `0x0001` в младшие 16 бит регистра управления.

* **Плюсы:** Код короче (всего две инструкции), не использует и не затирает регистр `eax` вообще (параметр `preserve_eax` здесь игнорируется).
* **Минусы:** Устаревший (deprecated) метод. Инструкция `lmsw` может затирать или игнорировать старшие биты современных процессоров.
* **Вердикт:** **Для олдскула.** Полезно, если нужно сэкономить пару байт в загрузочном секторе и не хочется возиться с `eax`.

### 4. Битовый сброс/установка (`method="bts"`)

Использует инструкцию `bts eax, 0` (Bit Test and Set), которая проверяет и гарантированно выставляет 0-й бит регистра `eax` в единицу.

* **Плюсы:** Четкая атомарная работа с конкретным битом.
* **Минусы:** Инструкция `bts` выполняется процессором чуть дольше, чем обычный `or`.
* **Вердикт:** **Хорошая альтернатива.** Чуть медленнее, чем `or`, но работает так же надежно.

## 📋 Сводная таблица для новичков

| Метод | Затирает `eax` по дефолту? | Безопасность | Рекомендуется к использованию? |
| --- | --- | --- | --- |
| **`or`** | Да (если `preserve_eax=False`) | 🚀 Высокая | **Да, по умолчанию.** |
| **`bts`** | Да (если `preserve_eax=False`) | 🚀 Высокая | **Да**, если нравится инструкция `bts`. |
| **`lmsw`** | ❌ Нет, использует `ax` | ⚠️ Средняя | **Только для экономии места** или ретро-тестов. |
| **`inc`** | Да (если `preserve_eax=False`) | 🛑 Низкая | **Нет**, может сломать соседние биты `cr0`. |

## ⚡ Обязательный дальний прыжок (`jump_protected_mode`)

Установки бита в `cr0` **недостаточно** для полноценной работы в 32-битном режиме. Процессор продолжает исполнять инструкции в старом 16-битном конвейере. Чтобы завершить переход, необходимо выполнить дальний прыжок (Far Jump).

Фреймворк предоставляет для этого метод:

```python
boot.jump_protected_mode(address="0x08")

```

### Что делает этот метод под капотом

1. **Генерация дальнего прыжка:** Вставляет инструкцию `jmp address:protected_mode` (по умолчанию `jmp 0x08:protected_mode`), где `0x08` — это селектор сегмента кода в твоей таблице GDT.
2. **Очистка конвейера:** Этот прыжок принудительно очищает конвейер префетча процессора, сбрасывая старые 16-битные инструкции, и загружает новый селектор сегмента в регистр `cs`.
3. **Смена разрядности:** Автоматически добавляет директиву компилятора `[bits 32]` сразу после метки `protected_mode:`, переключая NASM в режим генерации 32-битного машинного кода.

## 💻 Пример использования

Полный цикл переключения процессора в защищенный режим выглядит следующим образом:

```python
from pylowlvl_os.x86_64.pyabstract import PyLowLvl

boot = PyLowLvl()
boot.init_enviroment16()

# 1. Включаем защищенный режим в cr0
boot.enable_protected_mode(method="or")

# 2. Делаем обязательный дальний прыжок для очистки конвейера и переключения в 32 бита
boot.jump_protected_mode(address="0x08")

boot.stoooop()

```
